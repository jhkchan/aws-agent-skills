# /aws:deploy-eventbridge-pipe

Activate the `eventbridge-pipe-deployer` skill and produce a
deployment plan for a production-grade Amazon EventBridge Pipe with
secure defaults.

## What it does

Reads a deployment specification (source type and ARN, optional
filter pattern, optional enrichment, target type and ARN, batch
window and size, DLQ, IAM role) and produces an ordered deployment
plan with:

1. Pre-flight specification gate — validates source ARN resolves in
   the matching region and is in the right state (ENABLED for
   streams, ACTIVE for Kinesis/MSK, RUNNING for MQ, queue exists
   for SQS), target ARN resolves and resource policy allows
   `pipes.amazonaws.com` (or the pipe role), DLQ policy grants the
   pipe role, IAM trust policy scoped with SourceAccount and
   SourceArn. Blocks deployment (PREREQUISITES_MISSING) on missing
   fields or invalid config.
2. Source selection — DynamoDB Streams, Kinesis, SQS, MSK, Amazon
   MQ, self-managed Kafka. Pipe owns the polling (not the target).
3. Filter pattern (optional) — JSON matching source raw record
   schema, max 4096 chars.
4. Enrichment (optional) — Lambda, Step Functions (Synchronous
   Express for enrichment), API Gateway, or API Destination.
5. Target — Lambda, Step Functions, EventBridge bus, SQS, SNS, ECS,
   API Gateway, API Destination, Redshift (Provisioned or
   Serverless), SageMaker Pipeline, or AWS Batch.
6. Batch windowing — `MaximumBatchingWindowInSeconds` (0-300,
   ignored for SQS source), `BatchSize` (source-specific cap),
   `MaximumRecordAgeInSeconds` (60-86400, streaming sources),
   `MaximumRetryAttempts` (0-185).
7. Dead-letter queue — pipe-level for streaming sources; source
   queue `RedrivePolicy` for SQS sources.
8. IAM role — least-privilege trust policy scoped to
   `pipes.amazonaws.com` with SourceAccount and SourceArn conditions
   (confused-deputy prevention).

Emits a deterministic deployment plan per pipe:

```text
PIPE: <name>
VERDICT: READY_TO_DEPLOY | PREREQUISITES_MISSING
TARGET: <name>
PRE_CHECKS:
  - [PASS] <check description>
  - [FAIL] <check description> — <reason>
STEPS:
  1. CONFIRM: About to <operation> pipe <name> in account <account>. Estimated monthly cost: <$X>. Proceed? (yes/no)
  2. <exact CLI command — no placeholders>
POST_VERIFY:
  - [PASS] <verification description>
SOURCE: <type> <arn> region <region>
FILTER: <none | JSON pattern>
ENRICHMENT: <none | type arn>
TARGET: <type> <arn>
BATCH: window <seconds> size <records> retry <count> age <seconds>
DLQ: <arn | source-queue redrive>
NOTES: <filter selectivity, retry behavior, cost posture>
```

## When to invoke

Provide a deployment spec and ask any of:

- "provision a DynamoDB Streams to Lambda pipe"
- "create a Kinesis to Step Functions pipe with 30s batch window"
- "MSK Kafka topic to AWS Batch job queue"
- "pipe with Lambda enrichment before Step Functions"
- "SQS queue to Lambda with DLQ"
- "Amazon MQ source pipe"
- "self-managed Kafka pipe with SCRAM auth"
- "filter pattern for DynamoDB Streams NewImage"
- "pipe-level DLQ vs source-queue RedrivePolicy"

A bare "source + target + deploy pipe" also routes here via the
orchestrator.

## Inputs

- **Required:** source_type (DynamoDB Streams, Kinesis, SQS, MSK,
  Amazon MQ, self-managed Kafka), source_arn, target_type (Lambda,
  Step Functions, EventBridge bus, SQS, SNS, ECS, API Gateway, API
  Destination, Redshift, SageMaker, AWS Batch), target_arn.
- **Optional:** filter_pattern, enrichment_type (Lambda, Step
  Functions, API Gateway, API Destination), enrichment_arn,
  batch_window_seconds (0-300), batch_size, record_age_seconds
  (60-86400, streaming sources), retry_attempts (0-185),
  dlq_arn, pipe_role_arn (or accept the default generated by this
  skill), OnPartialBatchItemFailure (AUTOMATIC_BISECT).

## Outputs

- One VERDICT block per pipe (READY_TO_DEPLOY or
  PREREQUISITES_MISSING).
- PRE_CHECKS with all dimensions validated (source state, region
  match, target resource policy, enrichment grants, DLQ topology,
  IAM trust scope).
- STEPS with ordered `aws pipes create-pipe` and `start-pipe`
  commands plus any prerequisite IAM/DLQ setup, starting with the
  CONFIRM gate.
- POST_VERIFY with verification steps (describe-pipe returns
  CurrentState=RUNNING; sample record triggers target within
  window; poison record lands in DLQ).
- NOTES with filter selectivity, retry behavior, and cost posture.
