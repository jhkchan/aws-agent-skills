# End-to-end usage scenario: codebuild-project-auditor

A walkthrough showing the skill auditing a CodeBuild project that
combines three findings: privileged mode on a non-Docker build
(PRIVILEGED — worst verdict), a plaintext secret (SECRET_LEAK — second
worst), and a wildcard service role (OVERPERMISSIVE_ROLE — third). The
severity aggregation, the secrets-resolution pipeline reasoning, and the
"rotate the leaked credential" assume-breach workflow are demonstrated.

## Input (user prompt)

> Review this CodeBuild project before we hand it to the new CI squad.
> It builds a Java service and deploys to staging. The build role was
> generated by the console years ago.

```json
{
  "name": "payments-ci",
  "source": {
    "type": "GITHUB",
    "buildspec": "version: 0.2\nphases:\n  build:\n    commands:\n      - mvn clean install\n      - aws s3 cp target/app.jar s3://payments-artifacts/"
  },
  "environment": {
    "type": "LINUX_CONTAINER",
    "image": "aws/codebuild/standard:7.0",
    "computeType": "BUILD_GENERAL1_SMALL",
    "privilegedMode": true,
    "environmentVariables": [
      {"name": "DEPLOY_TARGET", "value": "staging", "type": "PLAINTEXT"},
      {"name": "STRIPE_SECRET_KEY", "value": "sk_live_abcDEF1234567890xyz", "type": "PLAINTEXT"}
    ]
  },
  "serviceRole": "arn:aws:iam::111111111111:role/service-role/CodeBuild-payments-ci",
  "badgeEnabled": true,
  "logsConfig": {
    "cloudWatchLogs": {"status": "ENABLED"},
    "s3Logs": {"status": "DISABLED"}
  },
  "artifacts": {"encryptionDisabled": true},
  "vpcConfig": {
    "vpcId": "vpc-aaa",
    "subnets": ["subnet-public-1", "subnet-public-2"],
    "securityGroupIds": ["sg-all-egress"]
  }
}
```

Service role identity-based policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:*"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": "iam:PassRole",
      "Resource": "*"
    }
  ]
}
```

## Output (auditor)

```text
PROJECT: payments-ci
VERDICT: PRIVILEGED
REASON: environment.privilegedMode is true and the inline buildspec contains
no Docker commands (Step 1) — host-equivalent container privilege with no
Docker justification. The project also leaks STRIPE_SECRET_KEY in plaintext,
grants the build role s3:* and iam:PassRole on "*", and writes artifacts
without SSE-KMS.
FINDINGS:
  - [PRIVILEGED] privilegedMode=true with non-Docker buildspec (Step 1) — Maven build, no docker/buildctl
  - [SECRET_LEAK] environmentVariables[STRIPE_SECRET_KEY] type=PLAINTEXT — credential committed to project config (Step 2)
  - [NO_ENCRYPTION] artifacts.encryptionDisabled=true (Step 3b) — build output written without customer-managed SSE-KMS
  - [OVERPERMISSIVE_ROLE] service role grants s3:* on Resource=* (Step 4c) AND iam:PassRole on Resource=* (Step 4b)
  - [CONFIG_GAP] badgeEnabled=true — public build-status URL (Step 6)
  - [CONFIG_GAP] vpcConfig uses public subnets only (Step 5b) — VPC adds no isolation
REMEDIATION:
  1. Disable privilegedMode:
     aws codebuild update-project --name payments-ci --no-privileged-mode
  2. Rotate STRIPE_SECRET_KEY immediately (it was visible in CloudTrail
     for the lifetime of the project config) and move to Secrets Manager:
     aws secretsmanager create-secret --name payments/STRIPE_SECRET_KEY --secret-string <new-value>
     aws codebuild update-project --name payments-ci --secrets-manager-arn arn:aws:secretsmanager:...:secret:payments-STRIPE_SECRET_KEY-XXX
  3. Audit CloudTrail BatchGetProjects calls during the exposure window —
     any principal with codebuild:BatchGetProjects read the plaintext key.
  4. Scope the service role: replace s3:* with s3:PutObject on
     arn:aws:s3:::payments-artifacts/*. Remove iam:PassRole entirely
     unless the build truly passes a role (then scope to that specific
     role ARN with iam:PassedToService).
  5. Scope the trust policy to the project ARN:
     add Condition StringEquals aws:SourceArn arn:aws:codebuild:...:project/payments-ci
  6. Enable SSE-KMS on artifacts with a customer-managed key:
     aws codebuild update-project --name payments-ci --artifacts encryptionDisabled=false --encryption-key arn:aws:kms:...:key/abc
  7. Disable the badge:
     aws codebuild update-project --name payments-ci --no-badge-enabled
  8. Move the build to private subnets; the current public-subnet
     placement provides no isolation over the default network.
```

## Key reasoning the skill surfaces

- **The verdict is PRIVILEGED, not SECRET_LEAK.** Although the leaked
  Stripe key is the most operationally urgent finding, the strict
  priority order (PRIVILEGED > SECRET_LEAK > NO_ENCRYPTION >
  OVERPERMISSIVE_ROLE > CONFIG_GAP > OK) places privilegedMode at the
  top. Privileged mode is host-equivalent container compromise — an
  attacker who reaches the build can escape into sibling containers via
  the Docker socket.
- **The Stripe key requires rotation, not just moving.** The plaintext
  value was committed to the project config and visible via the API for
  the entire lifetime of the project. Anyone with `codebuild:BatchGetProjects`
  read access saw it. Moving it to Secrets Manager stops future exposure
  but does NOT undo past exposure — the key must be rotated at Stripe.
- **`iam:PassRole` on `"*"` is the privilege-escalation launchpad.** A
  malicious PR that modifies the buildspec can pivot into any deployment
  role in the account by running `aws deploy create-deployment
  --service-role-arn <any-role>`. The build role's permissions execute
  during every build, including builds triggered by PRs.
- **The VPC config is decorative.** A `vpcConfig` with public subnets
  provides no isolation over the default network — the build still has
  direct internet egress. The fix is private subnets + NAT gateway, not
  adding more security group rules.
- **The badge URL is publicly reachable.** Anyone who has seen the badge
  (e.g., embedded in a README) can fetch the latest build status
  indefinitely. Disabling the badge is the only way to revoke.
