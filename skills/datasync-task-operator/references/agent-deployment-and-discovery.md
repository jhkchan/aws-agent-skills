# DataSync Agent Deployment & Discovery Reference

Load this reference when planning an agent deployment, an agent
activation, or a DataSync Discovery job. Covers the agent lifecycle,
VM vs EC2 deployment trade-offs, activation-key mechanics, security
group requirements, Multi-Agent scaling, and the Discovery job
configuration surface.

## Agent lifecycle

```
[Deploy VM/EC2 image]
        │
        ▼
[Boot the agent AMI/VM]
        │
        ▼
[Browse to http://<agent-ip> in private network]
        │
        ▼
[Local console: enter Region + AWS account → activation key issued]
        │
        ▼
[Activation key valid for 24 h]
        │
        ▼
[aws datasync create-agent --activation-key <key> --agent-name <name>]
        │
        ▼
[Agent registers with DataSync control plane]
        │
        ▼
[describe-agent → Status: ONLINE, LastConnectionTime recent]
        │
        ▼
[Ready to be referenced by create-task --agent-arns]
```

The activation key is generated by the local agent process and is
valid for 24 hours. If the key expires, re-fetch a new one from the
local console. Once the agent is registered (`create-agent` returns
an `AgentArn`), the key is no longer needed.

## VM (on-prem) vs EC2 deployment

| Aspect | On-prem VM | EC2 instance |
|---|---|---|
| Use case | On-prem source (NFS/SMB/HDFS/Object Storage) reachable from a corporate DC | AWS-internal source (cross-VPC, cross-Region S3); or as a hop into on-prem via Direct Connect/VPN |
| AMI | DataSync agent VM image (`.ova`, `.vhdx`, `.qcow2`, or Hyper-V) | DataSync agent AMI from AWS Marketplace (search "AWS DataSync Agent") |
| Sizing | 4 vCPU / 8 GB RAM minimum for sustained 1 Gbps; 16 vCPU / 64 GB for 10 Gbps with NVMe | c5.2xlarge (8 vCPU / 16 GB) ~2 Gbps; c5.9xlarge ~7 Gbps |
| Storage | 80 GB scratch (logging, queueing) | EBS gp3 100 GB scratch |
| Network | 10 Gbps NIC ideal; 1 Gbps NIC saturates at ~1 Gbps | Instance-type network cap (c5.large up to 10 Gbps with SR-IOV) |
| Activation | Local console at `http://<agent-ip>` (HTTP, port 80) | Same local console via the instance's private IP |
| Cost | DataSync $0.0125/GB transferred + VM hosting | DataSync $0.0125/GB transferred + EC2 instance-hours + DataTransfer |

## Security group rules (agent)

| Direction | Protocol | Port | Source/Destination | Purpose |
|---|---|---|---|---|
| Outbound | TCP | 443 | AWS DataSync service endpoint (`datasync.<region>.amazonaws.com`) | Control plane |
| Outbound | TCP | 2049 | NFS source server | NFS read |
| Outbound | TCP | 445 | SMB source server | SMB read |
| Outbound | TCP | 8020, 50070 | HDFS NameNode + DataNodes | HDFS read |
| Outbound | TCP | 443, 80 | Object Storage endpoint | Object Storage read |
| Outbound | TCP | 2049 | EFS mount target | EFS write (destination) |
| Outbound | TCP | 445 | FSx for Windows file system | FSx Windows write |
| Inbound | TCP | 80 (HTTP) | Operator network only | Activation-key fetch |
| Inbound | TCP | 22 (SSH) | Operator bastion only | Troubleshooting (optional) |

Never expose port 80/22 to the public internet. The activation-key
fetch is HTTP only — wrap it in a one-time session over a bastion or
VPN.

## IAM role for the agent

For an EC2 agent, attach an instance profile with:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "datasync:*"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "arn:aws:logs:us-east-1:111111111111:log-group:/aws/datasync/*"
    }
  ]
}
```

For an on-prem VM agent, the agent is authenticated via the
activation key exchange; no IAM role is required on the VM itself.
The DataSync service assumes the task role for source/destination
access.

## Multi-Agent scaling

A single task can leverage multiple agents for parallel throughput
(scales beyond a single agent's ~10 Gbps ceiling). Configure at the
task level via `--agent-arns` (list).

```bash
aws datasync create-task \
  --source-location-arn <src> \
  --destination-location-arn <dst> \
  --agent-arns arn:aws:datasync:us-east-1:111111111111:agent/agent-001 \
              arn:aws:datasync:us-east-1:111111111111:agent/agent-002 \
              arn:aws:datasync:us-east-1:111111111111:agent/agent-003
```

Caveats:

- The agents must all have network reachability to the same source
  and destination locations.
- Bandwidth throttle is enforced PER-AGENT. Three agents with
  `BandwidthLimitInMb: 1000` each yields 3,000 Mb aggregate.
- File-to-agent assignment is automatic and based on sharding; not
  configurable per-file.

## Snowball Edge agent

For air-gapped migrations, the agent runs on a Snowball Edge device.
Activate locally on the Snowball; ship the device to AWS; DataSync
ingests from the Snowball into S3.

Key constraints:

- Source location is the Snowball's local S3 endpoint.
- Destination is an S3 bucket in the customer account.
- The Snowball must be returned to AWS within the rental window.
- Pricing: DataSync $0.0125/GB + Snowball service fee (separate).

## Discovery job

A discovery job is a read-only assessment that connects to an
on-prem NFS or SMB storage system and collects capacity, performance,
and file-type metrics. It does NOT migrate data.

### Prerequisites

- A DataSync agent activated and `Status: ONLINE`.
- The agent can reach the on-prem storage system on the right port
  (2049 NFS, 445 SMB).
- The agent has read access to the storage (e.g., `Read` on the
  share).

### Create a discovery job

```bash
aws datasync start-discovery-job \
  --storage-system-arn arn:aws:datasync:us-east-1:111111111111:system/system-001 \
  --collection-duration-minutes 20160 \
  --client-token $(uuidgen) \
  --tags Key=env,Value=prod
```

- `CollectionDurationMinutes`: 20160 (14 days) or 40320 (28 days).
- `ClientToken`: idempotency token (UUID).
- The job is read-only.

### Stages

1. `STARTING` — agent connects to the storage system.
2. `RUNNING` — metrics collection ongoing.
3. `COMPLETED` — collection finished; recommendation report
   available within 4 hours.
4. `STOPPED` — operator stopped the job early (use
   `stop-discovery-job`).
5. `ERROR` — collection failed (storage unreachable, auth expired).

### Outputs

After completion:

- Capacity usage per share and per directory.
- Performance metrics (IOPS, throughput, latency) sampled at
  5-minute intervals.
- File-type histogram (extension-based).
- Cold-data distribution (files not accessed in N days, where N is
  30/60/90).
- Right-sizing recommendation: S3 tier (Standard, IA, Glacier),
  EFS size and throughput mode, FSx family recommendation.
- Migration wave plan: chunks by directory for sequenced cutover.

### Conflicting-jobs rule

Never run two discovery jobs against the same storage system at the
same time. The jobs will compete for metrics collection and produce
inconsistent recommendations. Use `list-discovery-jobs` to confirm
no in-flight job covers the same storage before starting a new one.

## Monitoring an agent

```bash
aws datasync describe-agent --agent-arn <agent-arn>
```

Key fields:

- `Status`: `ONLINE` (healthy) or `OFFLINE` (unreachable).
- `LastConnectionTime`: when the agent last phoned home to the
  DataSync control plane. Anything older than 5 minutes is suspect.
- `PrivateLink` configuration (if any).
- `Platform`: OS / version of the agent.

CloudWatch alarm recommended:

- Alarm on `Status == OFFLINE` for > 10 minutes.
- Alarm on `LastConnectionTime` older than 15 minutes.
